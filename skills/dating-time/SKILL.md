# dating-time

为正在约会的两人找当地正在或即将开始的高质量活动。

## 默认参数

- 城市：北京（除非用户指定）
- 时间窗：本周末（今天到周日 23:59；如今天是周五-周日则到下周日；如用户指定 "今晚/明天/下周/5月" 则按用户）
- 不限品类，按"浪漫"筛选

## 浪漫（核心选择标准）

唯一标准：**浪漫**。

不是烛光晚餐那种窄义——是"两人在场之后会想再去 / 离开之后还能聊很久 / 共同经历后多了一个内部梗"的氛围。这是个抽象词，由你按抓到的每条活动现场判断；同样一个"音乐节"在小型 livehouse 浪漫，在 5 万人的草地上不浪漫；同样一个"讲座"作家对谈浪漫，公司团建沙龙不浪漫。

绝对不浪漫（直接剔除）：
- 婚博会、招聘会、纯儿童活动、亲子主题
- 微商沙龙、传销式聚会、纯促销卖货、培训招生类
- 万人级超大型音乐节（人挤人无法对话）
- 电影院普通商业排片（首映礼 / 主创见面会除外）

其余一切交由你判断。**宁可多保留也不要漏掉**——把握不准的就排在后面，让用户自己挑。

⚠️ **同类压缩**：豆瓣 salon / commonweal / party 分类里有大量读书会 / 共读 / 心理治疗沙龙 / 搭子社交聚会，同质度极高且浪漫密度低——**每个同类最多保留 3 条**，其余直接省略，不写"另有 N 条"。

## 执行流程

按以下步骤，**并发执行所有抓取**（豆瓣 8 组 + WebSearch 7 组同一个 message 内一起发）：

### 第一步：并发抓取（一个 message 内全部发出）

**豆瓣同城（本地脚本并发抓取，wallclock ~6 秒）** — 一条 Bash 并发跑 9 路：

```bash
SCRIPT=~/.claude/skills/dating-time/scripts/fetch_douban.py
CITY=beijing  # 或 shanghai / guangzhou / shenzhen / chengdu / hangzhou / wuhan / nanjing / chongqing / xian
WHEN=week     # today / tomorrow / weekend / week / nextweek / future（按用户时间窗选）
for CAT in music drama commonweal salon exhibition film party sports comedy; do
  python3 "$SCRIPT" "$CITY" "$WHEN" "$CAT" > "/tmp/dt_${CITY}_${WHEN}_${CAT}.json" &
done
wait
```

脚本输出 **结构化 JSON**（ISO 8601 时间 + 完整地址），直接 `cat /tmp/dt_*.json | jq` 读取，**不再走模型抽取**。当日同参数自动命中缓存（< 0.1 秒）。

时间窗超过 1 周（如"3 周"），把循环再跑一次 `WHEN=future`（仍并发，总 wallclock 仍 ~6 秒）。

URL 模板（脚本内部用）：`https://www.douban.com/location/{city}/events/{when}-{cat}`

**WebSearch（8 组并发，默认全跑）** — 把 `{时间}` 替换为用户指定的时间窗（如 "本周末" / "2026年5月" / "今晚"）：
1. `{城市} {时间} 沙龙 演讲 对谈 思辨`
2. `{城市} {时间} 脱口秀 即兴喜剧 厂牌`
3. `{城市} {时间} 剧本杀 密室 桌游 主题`
4. `{城市} {时间} 当代艺术展 画廊 开幕 798 草场地`
5. `{城市} {时间} 市集 夜场 city walk 限时`
6. `{城市} {时间} livehouse 演出 排期 独立音乐`
7. `{城市} {时间} 艺术季 书市 设计周 电影节`
8. `{城市} {时间} 球赛 主场 赛程`（北京补 `国安 工体` / `首钢 五棵松` / `网球公开赛`；上海补 `海港 / 申花`；其他城市按当地球队名）

如果用户关键词包含「漫展/二次元/动漫」补一组：`{城市} {时间} 漫展 动漫 嘉年华`。

### 第二步：抽取与合并

- 豆瓣返回是结构化的，直接收
- WebSearch 返回是文本，从中抽取**具体活动名 + 时间 + 地点 + 链接**，能抽出几条算几条；模糊或无时间的丢弃（除非是"伞状大事件"，见下）
- "伞状大事件" 单独成块：识别条件 = 跨度 ≥ 7 天 + 含 N 场子活动 + 由官方/机构主办（艺术季/书市/电影节/设计周/嘉年华）
- 厂牌阵地单独成块：识别条件 = 长期常驻 + 周排片（如"周一至周日"，而非具体日期）

### 第三步：去重

- 同 url 直接合并
- 不同源同活动：标题 ≥ 80% 相似 + 时间相同 + 地点相同 → 合并，保留豆瓣 url（更稳定）

### 第四步：按品味画像过滤

逐条对照"剔除"清单，命中即丢。不输出任何"被过滤了什么"的说明。

### 第五步：分层输出

严格按下方格式，不加套话、不加解释、不加"祝你们玩得开心"之类。

## 输出格式

```
📍 {城市} · {时间窗描述}

🎪 伞状大事件
• {名称}（{起止日期}）{副标题/规模}
  {一句话亮点 ≤25 字} → {官方链接}
• ...

🎟️ 单场活动（按时间升序）
• {MM/DD 周X HH:MM} · {标题}
  {场地} · {区} · {票价 if 有} → {链接}
• ...

🏠 长期厂牌阵地
• {厂牌名} · {地段}
  {特色}（{周几演出}）→ {链接 if 有}
• ...
```

## 输出规则（强约束）

1. **不写开场白、不写总结**。开头直接是 `📍` 行。
2. **不解释品类含义**、不写"以下是为您筛选的活动"。
3. **每条活动必须含**：标题 + 时间 + 地点。**任何一项缺失即不输出**。
4. **链接必须是真实从抓取结果中拿到的**，不编造、不拼接。
5. 价格、艺人、规模等可选字段，**有则加，无则省**，不写"暂无"。
6. 单场活动按 start_time 升序，**最多 30 条**。如超过 30 条，只保留品味画像匹配度最高的 30 条。
7. 伞状大事件最多 5 个、厂牌最多 8 个。
8. 全程**中文输出**，简体。
9. **没有结果的板块整块省略**，不写"暂无"。

## 用户可选参数

- 指定城市：「上海周末有什么」→ `city=shanghai, when=weekend`
- 指定时间：「下周三晚上」/「5月10日」/「五一假期」→ 解析为具体时间窗
- 加关键词：「找个安静的」「想看演出」「室内」→ 在排序层加权
- 调整浪漫方向：用户加形容词（「更智性」/「更轻松」/「更刺激」/「更安静」/「带朋友一起」）→ 重新解读"浪漫"并加权

## 缓存

豆瓣抓取结果缓存到 `/Users/yupeng/.claude/skills/dating-time/cache/{城市}-{when}-{cat}-{YYYYMMDD}.json`，同日同参数命中即跳抓取。WebSearch 不缓存（信息变动快）。
